## v1.1 —— 精度校准（优先级最高）

**问题**：当前限额是统计下界，样本少的模型误差大。

- [ ] **人工校准表**：允许用户手动录入「某模型在已知消耗下触发了 429」，作为精确锚点
- [ ] **置信度字段**：`per_model_limits` 增加 `confidence`（按样本数与离散度打分）
- [ ] **离群值过滤**：剔除窗口内混入了其他模型消耗的样本
- [ ] **多窗口交叉验证**：同时用 12h / 24h / 48h 窗口反推，取一致性最好的 W

**验收标准**：在 ≥10 个模型的样本集上，与人工校准值的相对误差 < 15%。

## v1.2 —— 打通实时额度接口

**问题**：拿不到真实剩余额度（客户端令牌在 Electron DPAPI 安全存储）。

候选路径（按可行性排序）：

| 方案 | 描述 | 风险 |
| --- | --- | --- |
| A. 渲染层内执行 | 在客户端渲染进程上下文中调用 `POST /billing/meter/get-user-resource-summary`，返回 `usageTotal` / `usageLeft` / `refreshAt` | 低（只读，不改客户端） |
| B. IPC 透传 | 走客户端已有的 IPC 通道取额度 | 中（依赖客户端内部协议，版本升级易碎） |
| C. 维持日志反推 | 当前方案 | 无，但精度受限 |

- [ ] 验证方案 A 的可注入性
- [ ] 实现实时额度 + 估算值**双通道**，并给出置信度标注

**注意**：任何方案都不得提取或落盘客户端登录令牌。

## v1.4 —— 工程化

- [ ] **自动刷新**：定时任务定期更新 `limits.json` / `status.json`
- [ ] **多账号聚合**：支持多个 `WORKBUDDY_HOME` 的汇总视图

## v2.0 —— 主动防御

- [ ] **自动切换模型**：在 Skill 层面实现「预估即将超限 → 提前把任务切到备用模型」
- [ ] **任务分片**：超长任务按额度预算自动切分，跨窗口续跑
- [ ] **配额共享池**：多机 / 多账号额度协同调度

> ⚠️ v2.0 的自动切换涉及「质量不可控」问题，需要用户明确拍板策略与验收标准后再启动。

## 贡献指引

最欢迎的贡献类型：

1. **实测校准数据**：某 WorkBuddy 版本 / 某模型的限额实测值（能显著提升 v1.1 精度）；
2. **CodeBuddy CLI 适配**（v1.3）；
3. **实时额度接口方案**（v1.2）；
4. **其他平台适配**：任何「只在失败时才告知限额」的系统，都可以用本仓库的方法论反推阈值。
